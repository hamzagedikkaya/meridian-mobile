# Device QA — October 2026 (Noktürn v2)

The on-device half of the quality gate (design-analysis §8.7, §8.10-4,
WP-17). Everything the test suite can check without a phone is automated
(see `docs/design.md` §12); this list is what only the phone can tell.

**Status: not run — no device was attached when the redesign was finished.**
Every item below is marked *not run (no device attached)* with how to run it.
Fill in the result column (✓ / ✗ + a note or a screenshot path) on the
Android 16 phone.

## Setup

1. Phone: Android 16, 120 Hz panel, developer options on, USB debugging on.
2. A **profile** build for anything about frames or timing (debug builds are
   several times slower and mean nothing):
   `flutter run --profile -d <device-id>`
3. A server with a throwaway account (never the real one) for the flows that
   write: point Profil › Sunucu at it.
4. Settings to flip during the run: Settings › Accessibility › "Remove
   animations"; Settings › Display › Font size and Display size (largest);
   Settings › System › Navigation mode (gesture / 3-button); TalkBack.

## 1. Performance (§8.7)

Automated run (writes `build/<scenario>.timeline_summary.json` and fails on a
broken budget):

```sh
flutter drive --profile \
  --driver=test_driver/perf_driver.dart \
  --target=integration_test/perf_test.dart \
  -d <device-id>
```

It runs against the scripted API of the widget tests (500 transactions,
paged 50 at a time), so no server is needed and no data is touched.
